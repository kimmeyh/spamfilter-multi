# Status Footer -- portable setup prompt

**Purpose**: give Claude Code in ANY repo, on ANY machine, the same status-footer
behaviour this repo uses. Paste the prompt below into a fresh session in the target
repo. It is written so Claude builds the script itself rather than depending on a
file it cannot see.

**Why a prompt and not a file to copy**: the script reads sprint state from a path
convention, and other repos may use a different one (or none). A prompt lets Claude
inspect the target repo first and adapt, which a copied file cannot do.

---

## The prompt (copy everything between the lines)

---

I want every decision-point and milestone reply in this repo to end with a status
footer line, generated by a script rather than typed by hand.

**Target format:**

```
09/19/2026 1:06pm | Sprint 70 Phase 5.3 Manual Validation
```

That is: `<MM/DD/YYYY> <h:mmam|pm> | Sprint <N> Phase <n.n> <Phase Name>`.

**Before writing anything, inspect this repo and tell me what you find:**

1. Is there a machine-readable file holding the current sprint number and phase?
   Look for `.claude/sprint_status.json` first, then any similar state file. Tell me
   its path and the exact field names, or say plainly that none exists.
2. Where is the authoritative list of phase numbers and names (a workflow or process
   doc)? I need the footer to use real phase names, not invented ones.
3. Does this repo use sprints at all? If it does not, say so -- the footer should
   then be date and time only, and the rest of this is unnecessary.

**Then build it:**

- Write a script that prints the footer line. Use whatever language is already
  standard in this repo; do not introduce a new runtime dependency.
- **Read the live system clock every time.** Never reuse a timestamp from earlier in
  the conversation. This is the specific failure that motivated the script: a
  hand-assembled footer once reported a time an hour stale because it was copied
  forward from a previous message.
- Read the sprint number and phase from the state file you identified. If a value
  cannot be read, print the date and time plus an honest marker such as
  `phase unknown -- check <path>`. Never guess a phase, and never omit the line
  entirely.
- **Pin the locale.** Use invariant-culture formatting for both the time and the
  date. On a non-US machine a culture-sensitive `AM/PM` designator can render EMPTY
  and `/` can become `.`, silently producing a different format. Verify this by
  formatting under at least one non-US culture.
- Phase depth is `n.n` plus its name -- never `n.n.n`. If the source doc has deeper
  steps, round up to the `n.n` parent.

**Then verify, and show me the output of each check:**

1. The happy path: run it and confirm the line matches the target format.
2. The clock is live: run it twice a minute apart and show that the time changed.
3. Failure paths, which matter more than the happy path. Confirm it still prints a
   usable line when: the state file is missing, the state file is malformed, and the
   state file has no phase in it. It must never throw and never print nothing.
4. Locale: show the formatted output under a non-US culture.

**Then record it** in this repo's `CLAUDE.md` (or the equivalent instructions file)
with the exact command to run, so every future session uses the script instead of
assembling the line by hand.

**Do not** invent a phase name, omit the footer when a value is missing, or
reformat the date and time to a local convention. The format is fixed.

---

## Notes for the person pasting this

- If the target repo has no sprint state file, Claude should tell you so at step 1
  rather than inventing one. Decide then whether you want a date-time-only footer or
  whether to add a state file first.
- On a machine that already has a global instructions file (`~/.claude/CLAUDE.md` on
  Windows/macOS/Linux), a shared copy of the script placed alongside it applies to
  every repo on that machine at once. Per-repo setup is only needed when the repos
  are on different machines, or when a repo needs a different state-file path.
- This repo's own implementation is `.claude/hooks/status-footer.ps1`, with the
  measured performance rationale recorded in its header comment.
